# Medical — CRA / CRC 项目运营管理系统

面向 CRO / SMO 经营者的运营管理系统。核心命题：**管人、管钱、管风险**，不做受 GCP 监管的临床数据系统。

## 一句话定位

> CRO/SMO 卖的是人天。系统要回答的是"我的人有没有闲着、这个中心还赚不赚钱、下次报价该报多少"——
> 而不是"这个试验的数据干不干净"（那是 EDC 厂商的事）。

## 核心边界

| | |
|---|---|
| **做** | 项目·中心台账、中心启动与关闭、派工与产能、工时与差旅、里程碑与结算与**现金流预测**、质量事件与 CAPA、**审计轨迹**、经营看板、**客户与投标闭环**、报价模型 |
| **不做（第一阶段）** | EDC、ePRO、eConsent、IWRS、eTMF 主库、源数据 —— 受 GCP 监管，需完成 CSV 验证，自建风险过高 |
| **数据红线** | 不存任何受试者可识别信息，只存筛选号/随机号，优先只存计数 |
| **外部协作** | 医院机构办等外部方的权限是**另一个维度的切片**（按机构切行、按质量与合规切列），不是内部员工权限的子集 |
| **权限模型** | 行（看得到哪些中心）× 列（哪些字段可见）× 动作（能做什么）三维同时成立，外部角色默认拒绝、白名单加回 |

## 关键设计判断

最小作业单元是 **StudySite（项目 × 中心）**，不是项目。收入按中心计、成本按人落在中心上、
进度按中心统计、核查风险按中心暴露。"项目毛利 15%" 无经营价值，
"A 医院 40% / B 医院 -20%" 才可据以行动。

详见 [商业分析文档 §3.2](docs/01-商业分析与系统定位.md)。

第二个判断：**它既是管理系统，也是 CRA / CRC 干活的系统。**
管理层要的数全部来自一线的日常录入，而一线只会认真使用帮他干活的工具 ——
员工端做成管理端的只读切片，等于在源头上把整套系统架空。

第三个判断：**收入口径有两处方向相反的修正，都必须做。**
筛败费把收入调高（漏算会误砍高筛败中心），脱落扣减把收入调低（漏算会误保高脱落中心）。
只做一个，比两个都不做更危险 —— 因为它看起来是对的。


## 文档如何生成网页版

`docs/render.mjs` 是一个零依赖的 Markdown 渲染器，只覆盖本仓库文档实际用到的语法子集。
网页版由文档生成，两者不可能分叉：

```sh
node docs/render.mjs docs/03-开发需求与技术架构.md out/spec.html "中心台架构规格"
```
