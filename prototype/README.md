# 临床中心台 SiteDesk — 可交互原型

CRO / SMO 运营管理系统的**可交互原型**。单文件、自包含、无外部依赖（字体由 Google Fonts 提供，
离线时自动回退到系统字体栈）。直接用浏览器打开 `index.html`，**演示密码 `demo`**，
登录页列出可直接点击的演示账号。

> **全部数据为硬编码演示数据。** 公司、项目、医院、人员、受试者编号均为虚构，
> 不含任何真实受试者可识别信息 —— 这也是[系统设计文档](../docs/01-商业分析与系统定位.md) §2.3 定下的数据红线。

## 登录与权限

打开 `index.html` 先进登录页。**演示密码统一为 `demo`**，页面下方列出可直接点击的演示账号。
没有网络请求，不存任何真实凭据。

身份不再是一个下拉框，而是**由账号决定**。这不是包装 —— 权限在原型里是三个维度同时成立的：

| 维度 | 含义 | 例子 |
|---|---|---|
| **行** | 看得到哪些中心 | CRA 只看被指派的、PM 看本组承接项目下的、机构办只看本院、PI 只看自己担任研究者的 |
| **列** | 同一行里哪些字段可见 | CRA 看得到中心，但成本、毛利、报价一律显示 `—` |
| **动作** | 能对它做什么 | QA 能关闭质量事件，CRC 只能整改；只有 DM 能关闭数据质疑 |

**外部角色默认拒绝**：机构办与研究者的字段权限初始全关，靠白名单一项项加回来。
这与"先给全部、再关掉敏感的"在正常情况下结果一样，在**新增一个字段**时结果完全不同 ——
前者新字段默认不可见，后者新字段默认泄漏。

登录为**经营层**后进「组织与权限」，可以增减人员、建分组、把项目在组之间划转、
以及直接编辑上面这张三维表 —— **改完立即生效**：导航项、数据范围、字段遮罩同时变。
把「报价与合同金额」勾给 CRA，再登录林敏，客户台账的金额列会从 `—` 变成数字。

## 八种身份

**同一套数据，八种视角。** 设计前提：**它既是管理系统，也是干活系统。**
管理层要的数全部来自一线的日常录入，而一线只会认真使用帮他干活的工具 ——
员工端做成管理端的只读切片，等于在源头上把整套系统架空。

内部员工看不到公司毛利与报价模型；CRA/CRC 的工时页只显示本人记录且填报人锁定；
PM 看得到本组项目下全部中心，但只线管其中一部分人 —— 表格里的「跨组」标记就是这条边界。

**外部协作方的权限比内部员工更窄，不是更宽。** 机构办只看本院、只看质量与合规：
成本、毛利、人天、利用率、报价一概不开放 —— 那是受托方的商业信息，与机构履行监管职责无关。
反过来，机构的质控底稿也不向受托方开放全文，只发送质控意见与整改要求。

## 系统的入口：立项与建档

此前所有数据都是凭空存在的 —— 没有录入入口的系统，等于要求所有人先在别处把数据攒好再誊一遍。

- **项目立项**（PM 提交 → 经营层审批）：填参数时**实时用报价模型的口径算毛利率**，
  低于 25% 门槛立刻红色警示并给出保本合同额与缺口，提交后必须经营层签字。
  立项测算与报价模型共用同一套人天口径 —— 两套账是这类系统最常见的溃败方式。
- **中心建档**（PM 或 CRA）：医院、科室、PI、合同例数、单例单价、伦理路径、机构受理号、派驻人员；
  派驻时实时冲突检测（超载、CRC 跨城驻场、GCP 证书临期），建档后进入状态机第一节点，
  并**自动生成对应医院的机构备案申请**。
- 「已立项项目」表里的 **已建档 / 中心数** 差值 = 合同里写了但还没进系统的中心：
  它们的成本已经在发生，收入却挂不上号。建档滞后是早期成本失控最常见、也最不显形的一种。

## 质量事件的闭环：机构老师

此前质量事件是「我方发现、我方整改、我方关闭」—— 自己给自己打分。真实链条是跨组织的：

```
机构质控发现 → 出具质控意见 → 派发整改（落到具体 CRC 的「我的整改」）
            → 受托方提交整改回复 → 机构复核 → 关闭
```

原型里这条链是活的：机构办发起质控 → 逐项标记符合/不符合 → 提交后自动生成质量事件并派发；
切到 CRC 身份能在「我的整改」看到它，回复需写清措施与证据（字数校验）；
提交后转「待复核」，再切回机构办即可复核关闭或退回重做 —— 质控发现与质量事件两侧状态同步流转。

每条质量事件都带**发现来源**（中心自查 / 机构质控 / 内部监查 / 申办方稽查 / 药监核查），
并单列来源分布：**前置发现占比越高说明防线在起作用；如果问题主要由申办方稽查或药监核查发现，
代价就不再是整改，而是数据被剔除。**

## 四处结构性修正

原型此前有四个**源头上**的问题 —— 不是少了个功能，是账本身算错了：

**① 收入口径漏了筛败费 —— 这笔账在源头上是错的。**
行业筛败率 30%–50%，合同通常按入组单价的 35% 计筛败费。原口径 `收入 = 启动费 + 入组×单价`
既低估了成本（CRC 花在最终筛败者身上的工作量），又漏算了收入。补上之后演示数据收入 +14%，
**被误判为亏损的中心从 5 个减少到 4 个** —— 漏算筛败费会让高筛败率中心被误判亏损，从而砍掉本来赚钱的中心。
报价模型也加了筛败率参数，并给出「合同不含筛败费时单价须报多少」的谈判对照。

**② 受试者会因为做完一次访视就从系统里消失。**
现在受试者是有生命周期的对象：预筛 → 签 ICF → 筛选期 → 入组/筛败 → 按访视计划表（SOA）逐次访视 → 出组。
完成一次访视会自动生成下一次的窗口，**并且工时与访视在同一次录入** ——
分两次录的代价是「每次访视实际耗时」永远算不出来，而这正是报价模型最需要的输入。

**③ 看板上有两个硬编码数字。**
「SAE 24h 上报及时率」和「Query 平均关闭天数」原来是写死的，而同一页下方就摆着一条超窗的 SAE。
现在都由台账算出，SAE 上报时限台账逐条可查。

**④ 受试者没有「脱落」这个状态 —— 与①方向相反的同一类错误。**
`st` 原来只有 预筛 / 筛选中 / 已入组 / 筛败 / 已出组。撤回知情、失访、因 AE 终止治疗的受试者
在系统里**没有去处**：他会永远停在「已入组」、永远生成下一次访视窗口、永远刷红，
而且**按整例计收入**。现在按已完成访视比例计费：

```
脱落扣减 = Σ（1 − 已完成访视数 ÷ 计划访视数）× 单例单价
```

演示数据里 14 例脱落，收入相应调减 —— **筛败费把收入调高，脱落扣减把收入调低，两个都不做，
高筛败中心被误砍，高脱落中心被误保。** 中心详情抽屉里同时显示保留率与调减金额。

## CRC 的项目生命周期

原先的原型把「CRC 的生命周期管理」做成了「**受试者**的生命周期管理」—— 这是两件事。
受试者那条线是扎实的，中心那条线几乎空白：接手、启动、招募、维持、关闭，只做了中间的「逐次访视」。

| 阶段 | 补上的东西 |
|---|---|
| **接手** | **我的中心** —— CRC 终于看得见自己带的中心处在状态机的哪一节、合同还差几例、保留率多少、离关闭还差什么 |
| **启动** | **中心启动清单** —— 8 类 30+ 项，带负责人、应完成日、**阻塞项**标记与距计划 SIV 倒计时 |
| **招募** | **预筛登记** —— 漏斗的第一格终于有了门。按渠道统计转化率，不合格/拒绝必须填原因 |
| **维持** | **伦理事务**（年度跟踪 / 方案修订 / SAE 快报 / 严重违背 / 结题）、**SAE 上报入口**、**受试者退出登记** |
| **关闭** | **关闭闸门** —— 见下 |
| **贯穿** | **我的日程**（14 天时间轴 + 跨院冲突检测）、**交接**（8 项清单，含"在组受试者逐例交底"） |

**关闭闸门**：此前中心状态机的推进按钮全部逻辑是一句 `ss.st = next`，没有任何校验 ——
可以在药品差 3 盒、12 条质疑挂着的情况下把中心标成「中心关闭」。现在推进到
「SIV启动」要过启动清单的阻塞项，推进到「中心关闭」要过七道检查：

> 在组受试者、未关闭质疑、未关闭质量事件、药品数量不平衡、回收药品未销毁、
> 样本链未闭环、补偿未发放或缺签收凭证、未递交结题报告

拦截时不是禁用按钮，而是逐条列出**还差什么**并给出「去处理」的入口。
**中心状态机的每一次推进都对应真实世界的一组事实，系统的职责是断言这些事实成立，
而不是记录一个人点过按钮。**

**跨院冲突**：一个 CRC 同时带两三个中心是常态。「我的一天」按窗口剩余排序，回答"先做哪件"；
「我的日程」按日期铺开，回答"做不做得完、撞不撞车"。演示数据里 8-24 有两例访视分别在
北京协和与天津医科大学肿瘤医院 —— 这不是优先级问题，是物理上做不到，而这正是超窗的真正来源。

## 经营侧补上的五块

- **现金流预测** —— 此前只有后视镜（DSO、应收账龄），全是已经发生的。人力成本每月刚性支出
  （14 人 · 54.3 万/月），回款是里程碑制 + 账期。这一页回答的是"哪个月会没钱"。
  两个诚实之处：**已达成但不在开票队列的里程碑不计入回款**（那是记录缺口，不是未来收入，
  单独列出来 —— 这也是最快的现金杠杆）；另附**压力情景**（逾期应收再拖 3 个月、
  预计里程碑延后 1 个月）—— 基准情景假设逾期下月就能收回来，可它们之所以逾期，恰恰是因为对方还没打算付。
- **客户** —— 整套系统此前按「项目 / 中心」切片，`sponsor` 字段从没被当作可聚合维度用过。
  按客户看才答得了"这个客户今年给我多少、毛利率多少、应收拖多久、明年还续不续"，
  以及**客户集中度**（最大客户占比 >35% 会预警：议价权已经不在我们这边）。
- **投标与报价闭环** —— 报价模型算"按我们的人天该报多少"，这一页算"市场认不认"。
  中标结果必须回写，否则"我们是不是系统性报高"永远无法回答。
  演示数据里两次失标的复盘结论指向同一件事：**我们的每例人天假设比同行高**。
- **合同变更** —— 亏损第一大原因是入组延迟，第二大就是 scope creep 没有变更单。
  方案修订 → 每例多 1.5 人天 → 全项目 143 例就是 214 人天。**就算最终要不到钱也必须记下来**，
  因为下次报价时这就是该加进去的成本。
- **人才梯队** —— 卖的是人天，人走了产品就没了。流失风险分把已经散落在系统四处的信号加起来：
  利用率（两端都危险）、无继任者且负载重、司龄不足、已表达的诉求（"连续三周加班"本来就写在
  PM 的审批提示里）。并算出**交接成本** = 带中心数 × 3.5 人天 × 角色人天成本。

## 审计轨迹

此前原型里改任何东西都不留痕。在 GCP 语境下这不是缺个功能，**是整个系统不成立**。

每条轨迹回答四件事：谁（含当时的角色）、什么时候、改了什么（改前 → 改后）、**为什么**。
第四件最容易被省掉也最要命 —— 核查员看到"访视目标日从 08-18 改成 08-25"，
真正要问的从来不是"改了吗"，而是"为什么改"：是受试者确实改期，还是为了让超窗看起来没发生。

轨迹只追加、不可改删，权限类变更单独标色。这就是[架构文档](../docs/03-开发需求与技术架构.md) §4 里
`audit_log` 那张表长出来的样子。

## 补上的四块盲区

- **筛选漏斗与筛败分析**：预筛 → 签知情 → 入组/筛败 四格 + 筛败原因分布。
  自动判定落后中心的三种失败模式（预筛量不足 / 筛败率过高 / 中心未真正启动），三种对策完全不同。
- **中心可行性调查库**：PI 承诺按兑现系数打折、评分回溯校准、**override 理由强制留痕**。
  演示数据里两条覆盖理由是「申办方指定」和「为赶 FPI 凑中心数」—— 最后都由自己买单。
  问卷本身也在进化：「入排合格率」是复盘湘雅二 57% 筛败率之后才加进去的字段。
- **CRC 日常三件**：EDC 录入进度（访视后 5 个工作日为及时线）、受试者联系与改期状态、受试者补偿发放台账。
  再加上药品数量平衡（接收 − 发放 = 账面库存，实盘对不上就是严重发现）与生物样本链。
- **两个法定角色**：PI（确认访视、签署方案偏离、上报 SAE、授权分工表）与 QA（内部稽查 + **CAPA 有效性验证**）。
  QA 的价值不是再发现一批问题，而是验证 CAPA 防住了没有 —— 中心质量评级里「关闭后复发」权重最高。

### 各角色特有的机制

- **CRC · 访视窗口**：窗口由目标日 ± 窗口天数算出并倒计时，超窗即方案偏离。
  勾完全部访视任务后标记完成；若已超窗，系统**自动生成方案偏离质量事件**并落到质量模块。
- **CRA · 风险分级监查（RBM）**：风险分 = 入组落后 + 未关闭事件 + SDV 缺口 + 超期质疑，
  由四类客观信号合成，直接给出「加密监查 / 维持 / 可降抽样」的建议。
- **PM · 调配建议**：识别超载者后，先找同角色的组内余量（CRA 与 CRC 不能互相顶替），
  再看组外闲置者 —— 演示数据刻意构造成「组内无人可换、组外有人闲置」，
  这正是超载与闲置并存的典型成因：问题在组织，不在个人。
- **机构办 · 人员准入**：GCP 证书未提供或方案培训未完成的人，点「准予准入」会被系统拒绝。
  演示数据里的研究护士周琳资质材料缺失却已参与 3 例访视 —— 这在药监核查中是必查且必然被记录的严重发现。
- **机构办 · 立项受理**：材料未齐备时「予以受理」按钮禁用，只能发补正通知。
  材料不齐就受理，后面每个环节都带着这个缺口往下走。

| 派工与产能 | 角色筛选 · 人员详情 · **新增派工对话框**（实时冲突检测：超载、跨城驻场、GCP 证书临期） |

数据是活的，而且跨身份联动：CRC 标记一次超窗访视完成 → 质量模块多出一条方案偏离 →
经营层驾驶舱的风险预警随之增加；CRC 打一次卡 → 中心成本、毛利率、PM 的组内毛利一起变；
PM 移交一个中心 → 双方利用率、驾驶舱饱和度、该中心的 CRA/CRC 归属同步更新。
机构办质控一次 → CRC 的「我的整改」多一条待办 → 回复后机构复核关闭 → 质量事件同步关闭；
PM 立项通过审批 → 项目档案生成 → 可立即建档中心 → 中心进入状态机。
CRC 登记一例脱落 → 该中心收入调减、保留率下降 → 经营层的单中心毛利与客户毛利率同步变化。
经营层把某个模块从 CRA 角色上勾掉 → 林敏下次登录就没有这一项。
八种身份共用同一份内存数据与同一套计算口径。

## 设计系统 —— 「Instrument」

参照物不是仪表盘，是**仪表**：飞机面板、实验室天平、汽车中控屏。
排版承担全部重量；界面是一个平面，不是一摞卡片。

### 色彩：暖中性 × 冷强调色

温差是全部诀窍 —— 暖灰的纸面配冷调的钴蓝，才显得贵，而不是"又一个蓝色 SaaS"。

| 角色 | 明 | 暗 |
|---|---|---|
| 平面 | `#F7F6F3` 侧栏 / `#FFFFFF` 内容 | `#08080A` / `#101012` |
| 墨 | `#111112` / `#4A4A4D` / `#74747A` | `#F4F3F1` / `#A8A8AD` / `#8B8B93` |
| 发丝线 | `#EAE8E3` / `#DCD9D3` | `#212123` / `#2E2F32` |
| 强调（唯一） | `#1A56DB` | `#5A8CF5` |
| 语义（低饱和） | `#16794C` / `#8A5B00` / `#B3261E` | `#4EA97A` / `#CFA24F` / `#E4695C` |

**强调色是指示灯，不是装饰**：只出现在活动导航、焦点环、选中态、「实际」数据系列、健康区间刻度上。
主按钮用的是**墨色**（明色下是黑底白字），不是强调色 —— 这样强调色才始终代表"状态"。

**健康即常态，常态不着色。** 达成、健康、正常一律用墨色；只有 warn / crit 才抬高音量。
这一条把界面上的彩色数字从几十个压到个位数。

### 排版

- **DM Sans**（可变字重）—— 界面与标题。几何骨架、高 x 高度，不是 Inter。
- **DM Mono** —— 只用于编号、日期、代码块、小号标签。
- **数值用 DM Sans + `tabular-nums`，标识符用 DM Mono** —— 数值和编号是两类信息，视觉上就该分开。
- 中文回落 PingFang SC → Source Han Sans SC。

### 版面

- 左栏 236px，**纯文字导航、无图标** —— 分组与排版已经说清楚层级。
- 内容区用**发丝线与留白分区，不用盒子**。卡片只保留给真正悬浮的东西：抽屉、弹窗、提示。
- 指标是**一排被竖线分隔的数字**，不是磁贴。
- 表格无外框、44px 行高、数字列右对齐等宽、表头只有一条下规则。
- 圆角：控件 6px，悬浮层 10–12px，区块 0。投影只有一个令牌，只给悬浮层。
- 动效 140ms `cubic-bezier(.2,0,0,1)`；行悬停染底、按钮按下沉 0.5px、焦点 2px 强调色环；
  `prefers-reduced-motion` 全程尊重。

### 图表

跟着同一套语言收敛：

- **折线**：两系列封顶 —— 计划为灰色虚线（参考），实际为强调色实线带 5.5% 面积填充。
- **条形**：**颜色不承担识别职责** —— 每根条自带标签，统一用强调色。
- **堆叠**：单色序列，**深浅按占比自动排名分配**（`stacked()` 内置），深浅必须与量级一致。
- **双向**（单中心盈亏）：正值中性墨色，负值警报红 —— 红色只留给真正的坏消息。
- **利用率**：条形中性，健康区间用两道强调色刻度标出，状态落在数字的颜色上。
- 分类色板经明暗双模式 CVD 校验（`dataviz` validator）：双系列 ΔE 23.7 / 15.6，
  单色序列两模式 ordinal 全项通过。

### 无障碍与响应式

全部文本色对比度 ≥ 4.5:1（明暗双模式实测）；焦点态可见；表格与图表各自横向滚动，
页面本身在 390 / 834 / 1500px 下均无横向溢出。
