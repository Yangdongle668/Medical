# 临床中心台 SiteDesk — 可交互原型

CRO / SMO 运营管理系统的**可交互原型**。单文件、自包含、无外部依赖（字体由 Google Fonts 提供，
离线时自动回退到系统字体栈）。直接用浏览器打开 `index.html` 即可。

> **全部数据为硬编码演示数据。** 公司、项目、医院、人员、受试者编号均为虚构，
> 不含任何真实受试者可识别信息 —— 这也是[系统设计文档](../docs/01-商业分析与系统定位.md) §2.3 定下的数据红线。

## 五种身份

顶栏「身份」下拉可即时切换。**同一套数据，五种视角** —— 看得到什么、能做什么，由身份决定。

| 身份 | 数据范围 | 模块 |
|---|---|---|
| **经营层**（凌远 · 总经理） | 全公司 · 15 个中心 | 驾驶舱、立项审批、台账、入组、派工、工时、P&L、结算、质量、监查、报价 |
| **PM**（韩雪 · 项目总监） | 线管 7 人 · 负责 2 个项目 | 团队工作台、我的团队、待我审批、**立项与建档** + 项目/质量/财务 |
| **CRA**（林敏 · 高级监查员） | 自己派驻的 4 个中心 | 我的一天、我的中心（风险分级）、监查访视、数据质疑、我的整改、工时 |
| **CRC**（吴桐 · 高级协调员） | 驻场的 2 个中心 | 我的一天、受试者访视窗口、数据质疑、中心文件与物资、我的整改、工时 |
| **机构办**（张慧敏 · 机构项目管理员）<br>*医院方，非本公司员工* | 北京协和医院承接的全部项目 | 机构工作台、立项受理、机构质控、人员备案与准入 |

内部员工看不到公司毛利与报价模型；CRA/CRC 的工时页只显示本人记录且填报人锁定；
PM 看得到项目下全部中心，但只线管其中一部分人 —— 表格里的「跨组」标记就是这条边界。

**外部协作方的权限比内部员工更窄，不是更宽。** 机构办只看本院、只看质量与合规：
成本、毛利、人天、利用率、报价一概不开放 —— 那是受托方的商业信息，与机构履行监管职责无关。
反过来，机构的质控底稿也不向受托方开放全文，只发送质控意见与整改要求。

## 系统的入口：立项与建档

此前所有数据都是凭空存在的 —— 没有录入入口的系统，等于要求所有人先在别处把数据攒好再誊一遍。

- **项目立项**（PM 提交 → 经营层审批）：填参数时**实时用报价模型的口径算毛利率**，
  低于 25% 门槛立刻红色警示并给出保本合同额与缺口，提交后必须经营层签字。
  立项测算与报价模型共用同一套人天口径 —— 两套账是这类系统最常见的溃败方式。
- **中心建档**（PM 或 CRA）：医院、科室、PI、合同例数、单例单价、伦理路径、机构受理号、派驻人员；
  派驻时实时冲突检测（超载、CRC 跨城驻场、GCP 证书临期），建档后进入状态机第一节点，
  并**自动生成对应医院的机构备案申请**。
- 「已立项项目」表里的 **已建档 / 中心数** 差值 = 合同里写了但还没进系统的中心：
  它们的成本已经在发生，收入却挂不上号。建档滞后是早期成本失控最常见、也最不显形的一种。

## 质量事件的闭环：机构老师

此前质量事件是「我方发现、我方整改、我方关闭」—— 自己给自己打分。真实链条是跨组织的：

```
机构质控发现 → 出具质控意见 → 派发整改（落到具体 CRC 的「我的整改」）
            → 受托方提交整改回复 → 机构复核 → 关闭
```

原型里这条链是活的：机构办发起质控 → 逐项标记符合/不符合 → 提交后自动生成质量事件并派发；
切到 CRC 身份能在「我的整改」看到它，回复需写清措施与证据（字数校验）；
提交后转「待复核」，再切回机构办即可复核关闭或退回重做 —— 质控发现与质量事件两侧状态同步流转。

每条质量事件都带**发现来源**（中心自查 / 机构质控 / 内部监查 / 申办方稽查 / 药监核查），
并单列来源分布：**前置发现占比越高说明防线在起作用；如果问题主要由申办方稽查或药监核查发现，
代价就不再是整改，而是数据被剔除。**

### 各角色特有的机制

- **CRC · 访视窗口**：窗口由目标日 ± 窗口天数算出并倒计时，超窗即方案偏离。
  勾完全部访视任务后标记完成；若已超窗，系统**自动生成方案偏离质量事件**并落到质量模块。
- **CRA · 风险分级监查（RBM）**：风险分 = 入组落后 + 未关闭事件 + SDV 缺口 + 超期质疑，
  由四类客观信号合成，直接给出「加密监查 / 维持 / 可降抽样」的建议。
- **PM · 调配建议**：识别超载者后，先找同角色的组内余量（CRA 与 CRC 不能互相顶替），
  再看组外闲置者 —— 演示数据刻意构造成「组内无人可换、组外有人闲置」，
  这正是超载与闲置并存的典型成因：问题在组织，不在个人。
- **机构办 · 人员准入**：GCP 证书未提供或方案培训未完成的人，点「准予准入」会被系统拒绝。
  演示数据里的研究护士周琳资质材料缺失却已参与 3 例访视 —— 这在药监核查中是必查且必然被记录的严重发现。
- **机构办 · 立项受理**：材料未齐备时「予以受理」按钮禁用，只能发补正通知。
  材料不齐就受理，后面每个环节都带着这个缺口往下走。

## 十个经营层模块

| 模块 | 主要交互 |
|---|---|
| 经营驾驶舱 | 8 个 KPI 磁贴（点击跳转对应模块）· 入组曲线十字准星 · 时间范围切换 · 风险预警自动推导并可跳转 |
| 项目 · 中心台账 | 搜索 · 状态多选筛选 · 列排序 · 行点击开详情抽屉 · **状态机推进**（推进到 SIV 会自动生成待开票里程碑） |
| 入组进度 | 项目切换 · 累计/月度新增切换 · 逐中心小倍数卡片（灰线 = 计划到今日） |
| 派工与产能 | 角色筛选 · 人员详情 · **新增派工对话框**（实时冲突检测：超载、跨城驻场、GCP 证书临期） |
| 工时与差旅 | 手机端填报模拟 · 工作类型自动判定可计费/不可计费 · 提交后成本即时归集到 StudySite · 可撤销 |
| 成本与毛利 | 单中心毛利双向条（零轴居中）· 四种排序 · 成本构成堆叠 · 单中心 P&L 明细表 |
| 里程碑 · 结算 | 单笔开票 / 登记回款 / 一键批量开票 · 账龄分布 · DSO 实时重算 |
| 质量事件与 CAPA | 严重度筛选 · 事件展开 · **SAE CAPA 倒计时**（逐秒）· 验证关闭 |
| 监查访视 | 访视排期选择 · **MVR 跟进项勾选** · 跟进项未清零时拒绝提交监查报告 |
| 报价模型 | 8 个参数滑块实时重算 · 成本构成推演 · 人天分解 · **与历史实际成本对标** · 全部公式可追溯 |

数据是活的，而且跨身份联动：CRC 标记一次超窗访视完成 → 质量模块多出一条方案偏离 →
经营层驾驶舱的风险预警随之增加；CRC 打一次卡 → 中心成本、毛利率、PM 的组内毛利一起变；
PM 移交一个中心 → 双方利用率、驾驶舱饱和度、该中心的 CRA/CRC 归属同步更新。
机构办质控一次 → CRC 的「我的整改」多一条待办 → 回复后机构复核关闭 → 质量事件同步关闭；
PM 立项通过审批 → 项目档案生成 → 可立即建档中心 → 中心进入状态机。
五种身份共用同一份内存数据与同一套计算口径。

## 设计与工程约束

- **色彩**：蓝图青蓝为交互色；语义色（good/warn/crit）与品牌色分离；
  图表 5 槽分类色经色觉障碍可分辨性验证，明暗两套独立取值。
- **明暗双主题**：跟随系统，也响应查看端的显式主题标记。
- **利用率按状态着色而非高低** —— 闲置与超载都是问题，这是信息设计上的判断，不是配色偏好。
- 表格与图表各自横向滚动，页面本身不产生横向滚动；移动端 390px 宽度下可用。

## 修改方式

`index.html` 是**产物**，源在 `parts/`：

```sh
./build.sh     # 由 parts/*.html 重新拼接生成 index.html
```

|---|---|
| `parts/01-head.html` | 设计令牌与全部样式 |
| `parts/02-shell.html` | 页面骨架 + 项目/中心/人员/工时等主数据 |
| `parts/02b-roles.html` | 身份定义、受试者访视、数据质疑、审批队列、现场清单、SDV 进度 |
| `parts/02c-intake.html` | 机构办身份、立项申请队列、机构质控、人员备案、立项受理 |
| `parts/03-core.html` | 派生指标计算、抽屉/提示原语、图表原语 |
| `parts/04-nav.html` | 按身份分流的导航、路由、数据范围（`myScope`）、全局状态 |
| `parts/05-dash.html` … `10-price.html` | 经营层十个模块视图 |
| `parts/11-crc.html` | CRC 端：我的一天、访视窗口、数据质疑、中心文件与物资 |
| `parts/12-cra.html` | CRA 端：我的一天、我的中心（风险分级） |
| `parts/13-pm.html` | PM 端：团队工作台、我的团队、待我审批 |
| `parts/14-intake.html` | 立项与建档（PM 提交 / 经营层审批）、新建项目与中心建档表单 |
| `parts/15-inst.html` | 机构端四视图 + 受托方侧的「我的整改」 |
| `parts/99-boot.html` | 启动 |
